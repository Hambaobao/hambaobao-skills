# 引用检查与安全迁移


- 要移动既有材料时，先列明源、目标、原因、可控的引用、不可控使用方和恢复步骤；先读取 Git 状态、运行或占用情况，核对目标不存在且文件归属明确。路径变化涉及其他人、共享服务或未知依赖时先确认；不能确认安全就保留原路径，改用索引。
- 从已核实且不含凭据的相关文档、脚本和配置中查找旧绝对路径、相对于引用文件的路径写法及文件名。以当前工作区为例，先设定 `SCOPE`、`OLD_ABS` 和 `OLD_REL`，再使用以下只列出命中文件名的只读查找；按需逐个检查命中，不输出敏感内容：

  ```bash
  rg -l --hidden -F -- "$OLD_ABS" "$SCOPE"
  rg -l --hidden -F -- "$OLD_REL" "$SCOPE"
  rg -l --hidden -F -- "${OLD_ABS##*/}" "$SCOPE"
  ```

  `SCOPE` 应是预先核实、不含敏感文件的最小目录；必要时用 `--glob` 排除敏感路径。相对路径和文件名可能有多种写法，分别查找并人工判断；检查源文件内指向其他文件的相对引用。`rg` 返回 1 表示无匹配，其他非零值需查明错误。默认忽略规则、二进制、符号链接、运行时配置和工作区外消息不一定被搜索到。无法掌握的引用应如实列出，不把无命中当作没有依赖。
- 明确获准且依赖已厘清后，为本次范围保留可恢复副本和原路径记录，逐项移动并更新获准修改的引用；保留文件内容与必要权限。不要对用户数据、工作副本或外部系统执行自动批量移动或删除。不能修改旧消息或其他人的引用时，与责任人确认兼容路径或保留原位置；不要擅自创建指向敏感文件的兼容链接。
- 迁移后检查更改过的本地链接是否从各引用文件的位置可解析：例如对已核实的本地相对目标，运行 `realpath -e -- "$REF_DIR/$TARGET"`；链接片段、URL 及非文件路径另行判断。再重跑旧路径查找，核对文件集合、内容、权限和实际任务入口。抽查外部引用是否仍有效，不能验证的单独列出；失败时按已记录的恢复步骤还原本次变更。报告实际移动、保留、检查范围和未验证依赖。
