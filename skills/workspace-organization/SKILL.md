# Workspace Organization

从创建任务材料开始保持工作区清晰，让当前任务和历史材料可查找、可恢复；沿用工作区和项目已有约定，不强制统一目录。

## 默认工作区布局

没有既定项目约定时，新材料按以下职责组织；目录按需创建，已有路径和运行时所需目录保留原位：

```text
<workspace>/
  AGENTS.md                工作规则
  MEMORY.md                恢复入口及索引
  notes/                   跨任务的知识和决策
  tasks/<主题>/record.md   任务状态、决定、验证与产物位置
  tasks/<主题>/runs/       重复运行的产物，按需分批
  scripts/                 确实被多个任务复用的工具
  worktrees/               项目未指定位置时的工作副本
```

单个任务的计划、报告、脚本和验证材料放在其任务位置，不为每种材料新建根目录。`.raft/`、`.slock/`、`.agents/`、`.codex/`、`.claude/` 等运行时和技能目录由相应环境维护，整理时保留；已有工作规则文件同样保留，环境兼容设置由维护人员处理。

## 日常放置与收尾

- 开始任务先查适用项目规则与现有任务位置；新建多份材料时放到同一个任务位置，不把不同任务的文件散放在工作区根目录。没有既定命名时，用任务编号或主题命名，例如 `tasks/jobs-plan/`；相关任务、issue 和 PR 记在任务记录中。沿用现有可识别路径，不因命名不同而改名。
- 为有持续材料的任务创建 `record.md`，集中记录目标、状态、决定及产物位置；小任务只写必要内容。验证、日志和临时产物按需放入任务位置，不预建空目录；重复运行可按时间分组，记录适用的保留要求。较大产物存放于已核实有权限且适用的位置并记录路径；代码继续使用项目指定的工作副本。
- 创建任务材料、任务状态或关键位置变化时更新入口。`MEMORY.md` 记录角色、必要约束、知识索引和进行中任务的状态、路径及下一步；细节放到任务记录，避免重复。任务完成后从进行中列表移除，保留必要的历史指针；不能为了压缩长度删除恢复所需的重要信息。可按需参考 [记忆与任务记录模板](references/record-templates.md)。
- 已发布的 issue、PR 等外部文档以远端当前正文为准；修改前先读取，保留他人新增内容。本地底稿按实际用途和保留要求处理，保留必要的原文备份与交付证据。
- 交付时对照实际结果更新任务记录、最终证据路径和未完成事项；确认已有索引可找到材料，已完成任务优先保留原位。归档和清理只在权限、保留要求及路径依赖核实后进行；活动路径、运行文件、未提交工作区、仍被使用的文件以及凭据保持原位，不为符合目录规范而移动或复制。

## 盘点与规划

- 确认范围、所有权、允许的操作和适用规则。区分进行中任务、待验收代码、已完成但仍需保留的证据、可再生成的临时文件和用途不明的内容；记录与任务或 issue 的关联。不要把历史状态当成当前授权或运行状态。
- 优先为已有材料补充 `MEMORY.md` 或已有索引：写清任务、当前状态、关键决策和指向材料的路径；新任务按已有习惯分组，避免重复复制。活跃工作、运行文件、未提交 worktree 和外部依赖文件优先保持原位。
- 只删除经核实无用且在授权范围内的文件；自己创建的临时文件在确认不再使用、无需保留且无其他依赖后可按任务权限清理，并简记范围。其他人的文件或归属、用途不明的内容先保留并确认；用户数据、凭据和交付证据不按临时文件处理。不得把凭据值写入索引、日志、报告或备份，保存验证输出前检查并脱敏；不擅自移动、复制、上传密钥或改变权限。

## 引用检查与安全迁移

- 要移动既有材料时，先列明源、目标、原因、可控的引用、不可控使用方和恢复步骤；先读取 Git 状态、运行或占用情况，核对目标不存在且文件归属明确。路径变化涉及其他人、共享服务或未知依赖时先确认；不能确认安全就保留原路径，改用索引。
- 从已核实且不含凭据的相关文档、脚本和配置中查找旧绝对路径、相对于引用文件的路径写法及文件名。以当前工作区为例，先设定 `SCOPE`、`OLD_ABS` 和 `OLD_REL`，再使用以下只列出命中文件名的只读查找；按需逐个检查命中，不输出敏感内容：

  ```bash
  rg -l --hidden -F -- "$OLD_ABS" "$SCOPE"
  rg -l --hidden -F -- "$OLD_REL" "$SCOPE"
  rg -l --hidden -F -- "${OLD_ABS##*/}" "$SCOPE"
  ```

  `SCOPE` 应是预先核实、不含敏感文件的最小目录；必要时用 `--glob` 排除敏感路径。相对路径和文件名可能有多种写法，分别查找并人工判断；检查源文件内指向其他文件的相对引用。`rg` 返回 1 表示无匹配，其他非零值需查明错误。默认忽略规则、二进制、符号链接、运行时配置和工作区外消息不一定被搜索到。无法掌握的引用应如实列出，不把无命中当作没有依赖。
- 明确获准且依赖已厘清后，为本次范围保留可恢复副本和原路径记录，逐项移动并更新获准修改的引用；保留文件内容与必要权限。不要对用户数据、工作副本或外部系统执行自动批量移动或删除。不能修改旧消息或其他人的引用时，与责任人确认兼容路径或保留原位置；不要擅自创建指向敏感文件的兼容链接。
- 迁移后检查更改过的本地链接是否从各引用文件的位置可解析：例如对已核实的本地相对目标，运行 `realpath -e -- "$REF_DIR/$TARGET"`；链接片段、URL 及非文件路径另行判断。再重跑旧路径查找，核对文件集合、内容、权限和实际任务入口。抽查外部引用是否仍有效，不能验证的单独列出；失败时按已记录的恢复步骤还原本次变更。报告实际移动、保留、检查范围和未验证依赖。
